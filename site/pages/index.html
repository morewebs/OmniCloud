One panel for every provider you already pay.

OmniCloud aggregates server fleets, traffic allowances, billing, and a plan marketplace across cloud providers, behind one data model. The first question on the page is whether anything is down, and what this month will cost.

How the panel stays one panel

  • One model. Each provider adapter maps its API onto the same entities — server, address, allowance, invoice — and the interface renders only those. Adding a provider adds no new screens. The guide lists the eight.
  • Absent, not disabled. An action an adapter cannot do is missing from the row, never a greyed-out button.
  • Nothing is invented. The panel never guesses a billing model, and it never reports an action done because a provider answered 202. It waits until the provider's own view confirms the change.
  • The same routes, for scripts. Personal tokens reach the JSON API. A token scoped to IP change can swap one extra address and nothing else. Agents drive the same routes over MCP.

Look around before you install

A demo runs the real interface on mock data — 200 servers, orders, billing, one of them down — with no login and no provider account.
