Three ways in.

The demo needs nothing. Docker and a local checkout need a master key, which encrypts the provider credentials you add later. Production — TLS, backups, the reverse proxy — is in Deploy, not repeated here.

Demo

The real interface, mock data, no login. Python 3.12 and uv.

uv run python demo_server.py

Open http://localhost:8080.

Docker

One process, the database and the master key on a volume you back up together. Losing the key loses every stored credential.

docker build -t omnicloud .
docker run -d -p 8000:8000 \
  -v omnicloud-data:/data \
  -e OMNICLOUD_MASTER_KEY= \
  omnicloud

Generate the key the same way as the checkout below, and keep it: the container stores the database at /data/omnicloud.db and cannot read it without the key. The first visit creates the admin account and then closes forever.

From a checkout

uv sync
export OMNICLOUD_MASTER_KEY=$(uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())")
cd web && npm install && npm run build && cd ..
uv run uvicorn server.main:app --port 8000

Open http://localhost:8000. For day-to-day development the frontend runs separately on port 5173 and proxies the API; the guide has that command.

Then

  1. Add a provider account under Credentials. The form asks for what that provider's API needs, and only the last four characters are ever shown again.
  2. Leave Purchases off until you mean to spend money. IP changes and real orders do nothing on an account where it is off.
  3. Read Deploy before this faces a network, and Security for how to report a problem.
